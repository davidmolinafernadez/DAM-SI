## Objetivos

- Organizar materiales, actividades y prácticas por unidades didácticas.
- Facilitar el seguimiento del curso y la entrega de trabajos.
- Aplicar una estructura homogénea y hábitos básicos de control de versiones.

## Unidades didácticas

| Unidad | Contenido | Horas |
| --- | --- | ---: |
| [UD1](UD1/) | Arquitectura HW/SW, PRL y diagnóstico | 15 |
| [UD2](UD2/) | Fundamentos de sistemas operativos | 15 |
| [UD3](UD3/) | Instalación de sistemas y virtualización básica | 27 |
| [UD4](UD4/) | Redes TCP/IP, diagnóstico y redes virtuales | 28 |
| [UD5](UD5/) | Sistemas de archivos, particionado y copias | 20 |
| [UD6](UD6/) | Administración de sistemas operativos | 25 |
| [UD7](UD7/) | Recursos en red, seguridad y documentación | 30 |
| **Total** | | **160** |

Orden de impartición: **UD1 → UD2 → UD3 → UD4 → UD5 → UD6 → UD7**. Numeración vigente: UD3 Instalación y virtualización; UD4 Redes.

Reparto orientativo por evaluaciones: **55 + 50 + 55 horas**, permitiendo continuar UD3 en la segunda evaluación. Consulta la [secuencia vigente](Guias/Secuencia_2026_11_05.md) y el [itinerario de 27 horas de virtualización](UD3/Teoria/itinerario.md).

Cada unidad contiene cuatro apartados:

- `Teoria`: apuntes, presentaciones y material de consulta.
- `Activitats`: ejercicios breves y tareas de aula.
- `Practiques`: trabajos prácticos y entregables.
- `Recursos`: enlaces, herramientas y ficheros de apoyo.

## Guía de uso

1. Accede a la unidad didáctica correspondiente.
2. Consulta el material de `Teoria` y `Recursos`.
3. Realiza las propuestas de `Activitats` y `Practiques`.
4. Usa [Plantilles/plantilla-practica.md](Plantilles/plantilla-practica.md) como punto de partida para documentar una práctica.
5. Guarda cada material en su apartado y utiliza nombres de archivo claros.

## Validación automática

El flujo de GitHub Actions comprueba la sintaxis básica de los documentos Markdown y confirma que la estructura esencial del repositorio está presente. No necesita secretos ni código de aplicación.

## Convenciones

- Redacta los documentos en español o valenciano neutro y con lenguaje claro.
- Evita subir contraseñas, datos personales, binarios generados o archivos temporales.
- Describe cada cambio con un mensaje de commit breve y significativo.
